## この資料の役割

英語圏の教則・分析から得た技法を、そのまま表面模倣せず、日本語の音韻・統語・文化へ変換するための実務ガイドである。個別の韻技法の定義集ではない。出典の詳細は `source-ledger.yaml` の同一 ID を参照する。

日本語を「モーラ拍」、英語を「強勢拍」と見るのは有用な初期モデルだが、どちらも完全な等時性を持つという意味ではない。実作では録音とビート上の発音を優先し、文字列だけで韻やフロウを判定しない。  
根拠: [src:cambridge-mora-syllable], [src:manabe-2006], [src:adams-2009]

## 移植の原則

1. **機能を移し、音の形をコピーしない。**  
   「行末で期待を作る」「内部韻で推進力を出す」「アクセント位置をずらして緊張を作る」など、技法が担う機能を抽出して日本語で再設計する。
2. **綴りでなく、実際の発音列で判定する。**  
   日本語は読みをモーラへ分解し、母音列、子音の近さ、特殊モーラ、語境界を別々に見る。
3. **語よりフレーズを単位にする。**  
   日本語は助詞・助動詞を含む短い句を組み替えやすい。単語一個の完全一致だけを狙うと、語尾と文法が単調になる。
4. **韻とフロウを別々に設計し、最後に統合する。**  
   同じ韻でも、着地位置、音価、休符、発話速度、前後の子音で聴感が変わる。
5. **文化的記号ではなく構造を借りる。**  
   AAVE、地域スラング、固有のアドリブ、実体験を装う語りは、技術移植の必須要素ではない。

## 技法別の移植マトリクス

| 英語圏での考え方 | 日本語への変換 | 実装・執筆時の判定 | 注意点 |
|---|---|---|---|
| End rhyme / line-end rhyme | 行末・小節末・意味句末の母音列または近似音を対応させる | 読みの末尾 `2–5` モーラを比較し、着地拍も記録する | 「〜ない／〜たい」のような同一文法語尾の連発だけで成立させない |
| Internal rhyme | 一行・一小節の中に複数の着地点を作る | 行内の韻位置を拍番号で持つ。行末韻とは別系列でもよい | 文字上の一致より、実演時に聞き取れる間隔と強調を優先 |
| Multisyllabic rhyme | 複数モーラの母音列、または複数語にまたがる句の音列を対応させる | 例: `CV/CV/N` の完全一致だけでなく、母音核と拍数を段階評価 | 英語の「syllable」を日本語の「文字数」に置換しない |
| Slant / near rhyme | 母音一致を軸に、子音類似・モーラ数・リズム位置を加点する | 完全一致、母音一致、子音近似、リズム対応を別スコアにする | 「母音が同じなら全部同じ強さ」としない。子音の近さにも段階がある |
| Mosaic / phrase rhyme | 一語対一語でなく、一語対複数語・複数語対複数語で対応させる | 語境界を無視した発音列と、意味句としての自然さを両方確認 | 分かち書き上の見栄えに引っ張られない |
| Chain / linked rhyme | 複数行にまたがる韻系列、または前行末から次行内部への連結 | `A-A-A` だけでなく `A(internal)-A(end)-B(internal)` を地図化 | 用語は文献・現場で揺れるため、名称より位置図を保存 |
| Assonance | 母音列の反復として直接利用しやすい | 長母音、連母音、無声化しうる母音も実演で確認 | 仮名の見た目と録音上の母音が一致しない場合がある |
| Consonance / alliteration | 語頭・語中の子音反復、調音位置の近い子音群へ拡張 | 同一子音と近似子音を区別し、破裂・摩擦などの質感も記録 | 日本語では母音を伴うため、子音だけを孤立評価しない |
| Stress placement | 強勢の代わりに、拍頭、句アクセント、声量、長さ、音高、休符で知覚的な重みを作る | 「どのモーラを目立たせるか」を指定し、実演で検証 | 日本語のピッチアクセントを英語の強勢と同一視しない |
| Syncopation | 語頭・意味の核・韻着地を強拍から外し、次の拍へ解決する | オンセットを細分拍で記録し、前ノリ／後ノリも試す | ずらすこと自体を目的化せず、聴き取りやすい基準点を残す |
| Enjambment | 文・意味句を行末や小節線で完結させず、次へ流す | 行割り、意味の切れ目、呼吸位置を別フィールドにする | 紙面上の改行と実演上の区切りを混同しない |
| Cadence | 音高・音価・語尾の形・休符を含む句の輪郭として移す | 同じ文言で最低2種類の着地を録音比較する | 「フロウ」の同義語として曖昧に使わず、何が反復するか明記 |
| Pocket | ビートに対する一貫した微細タイミングと音価の配置として扱う | キック、スネア、ハイハットに対するオンセット／オフセットを記録 | 客観的な一点ではなく、演者と曲調に依存する実務語 |
| Punchline / setup-payoff | 前提、方向づけ、反転、着地を日本語の語順で再構成する | オチを最後の内容語へ寄せる、または助詞で保留して次行へ送る | 英語の語順を直訳して説明過多にしない |
| Storytelling / scene writing | 場面、主体、欲求、障害、変化を短いショットとして並べる | 各4小節に「新情報」または「視点変化」があるか確認 | 韻密度が因果関係や話者の一貫性を壊していないか監査 |
| Repetition / refrain | 同一フレーズを、発音・音価・文脈の変化で再提示する | 反復ごとに意味、声色、前後の一つ以上を変える | 語彙不足による重複と意図的反復を区別 |

根拠: [src:kawahara-2007], [src:tsujimura-davis-2009], [src:adams-2009], [src:ohriner-2019], [src:duinker-2022], [src:bradley-2009], [src:edwards-2009]

## 既存の日本語仕様へ接続する

この資料では比較と変換規則だけを定める。実装の詳細は次へ委譲する。

- 読みの正規化、モーラ、長音、撥音、促音、発音変異: `japanese-phonology.md`
- 辞書、G2P、未知語、コードスイッチ: `g2p-and-dictionaries.md`
- 韻候補の多軸採点、内部韻、連鎖韻: `rhyme-scoring.md`
- 拍グリッド、ポケット、呼吸、実演監査: `flow-and-cadence.md`

英語圏の資料から上記仕様へ渡す際は、次の境界を守る。

| 英語圏の入力概念 | 渡す先 | 変換時に失ってはいけない情報 |
|---|---|---|
| syllable | 音韻仕様 | 一つ以上のモーラになりうること、実演上の長さ |
| lexical stress | フロウ仕様 | 拍位置、音高、音価、声量のどれで目立つか |
| rhyme pair | 韻採点 | 語境界を越えた発音列、韻位置、意味上の役割 |
| onset grid | フロウ仕様 | ビート相対位置、休符、前後ノリ |
| pronunciation dictionary | G2P仕様 | 通常読みとテイク固有発音を分離した候補・信頼度 |

日本語ラップの半韻では子音類似性が段階的に知覚されるという分析があるため、英語圏の完全韻／不完全韻というラベルだけを二値で移さない。[src:kawahara-2007]

英語圏のフロウ分析が扱うオンセット、長さ、休符、アクセント、ビートとの位相は日本語でも有効な観測変数である。ただし、英語の語彙的強勢を日本語のピッチアクセントや拍頭へ一対一対応させない。[src:adams-2009], [src:ohriner-2019], [src:duinker-2022]

## 日本語の統語を活かす

- 助詞を使って述語やオチを保留し、次の句へ送る。
- 主語省略を活かし、音数を節約する。ただし話者が不明になる箇所では戻す。
- 修飾部を先に積み、最後の内容語で意味と韻を同時に着地させる。
- 倒置は意味の焦点を作るときだけ使う。韻のためだけの連続倒置は避ける。
- 文法語尾を韻の主役にしない。直前の内容語まで含むフレーズ韻へ広げる。
- 和語、漢語、外来語は音の密度と印象が異なる。曲の人物像と場面に合わせて混ぜる。

## 直接移植しないもの

次は「英語圏らしさ」を出す近道に見えても、技法そのものではない。

- AAVEや地域方言を、背景・話者設定なしに表面コピーすること
- 特定アーティスト固有の口癖、アドリブ、タグ、希少な比喩の反復
- ギャング、貧困、差別、犯罪、薬物などの経験を事実のように捏造すること
- 英語の語順、冠詞、複数形を日本語へ逐語的に残すこと
- 英単語を挿入するだけでグローバルなフロウになったとみなすこと

文化的なローカライズは、輸入形の単純コピーではなく、地域の言語資源と社会状況を通じた再創造として分析されている。[src:manabe-2006]

## 用語の揺れを処理する

`multisyllabic rhyme`、`compound rhyme`、`chain rhyme`、`cadence`、`pocket` などは、教則・研究・現場で意味が一致しない。スキルの内部表現では、名称だけでなく次を保存する。

```yaml
technique_label: internal_multimora_rhyme
sound_span_morae: 4
phrase_span_tokens: 2
positions: [bar_1_beat_2e, bar_1_beat_4]
vowel_match: high
consonant_match: medium
delivery_note: second landing delayed
```

用語が衝突した場合は、ユーザーの定義を優先し、位置・音列・機能を平易な日本語で言い換える。

## 移植後の監査

- 韻候補は仮名表記でなく、実際の発音と録音で確認したか。
- 英語の音節数を日本語の文字数へ機械置換していないか。
- 強勢の機能を、拍位置、長さ、音高、声量、休符へ分解したか。
- 文法語尾の一致を除いても韻網が残るか。
- 韻密度を下げた方が意味、場面、人物像が明確になる箇所はないか。
- 参考アーティストの表面特徴ではなく、機能レベルの設計になっているか。
- ビート上の一貫性と、意図した逸脱の両方が説明できるか。
