## 目的

この資料は法的助言ではない。既存曲や実在アーティストを参照しながらも、特定作品の代替物や本人作と誤認される出力を避け、技法を安全に抽象化してオリジナルの日本語ラップへ変換するための制作手順である。

著作権は一般にアイデアや方法そのものではなく、その具体的な表現を保護する。いっぽう、声・容貌など本人性の模倣には、著作権だけでは整理できない問題もある。[src:usco-copyright-basics], [src:usco-digital-replicas-2024]

## 基本境界

### 抽象化して利用できる対象

- 韻の密度、位置、長さ、近似度
- 行・小節・セクションの構造
- シンコペーション、休符、速度変化などの一般的リズム操作
- セットアップから反転・着地へ進む構造
- 視点、時制、場面転換の方法
- 語彙の抽象的な明暗、硬軟、具体度
- フックの反復回数や、反復ごとの意味変化

### 再現・移植しない対象

- 既存リリックの文、行、連、特徴的な語順
- 作品を想起させる希少な比喩、造語、固有名詞の組み合わせ
- 特定人物固有の決め台詞、タグ、アドリブ、表記癖
- 既存曲と同じ主題・場面順・韻語・オチを組み合わせた骨格
- 本人の未発表曲、新曲、リーク、失われたヴァースを装うもの
- 本人が書いた、歌った、承認したと誤認させる表示
- 実在人物の声質そのものを再現するための指示

「作風」には保護されない一般的技法が含まれうる一方、具体的表現の近接や本人性の偽装は別問題である。安全側では、名前をそのまま生成条件にせず、一般技法へ分解してから新しい題材・語彙・構造を作る。

## 名前付き参照を技法ベクトルへ変換する

ユーザーが「Xっぽく」「Xの新曲として」と依頼した場合は、次の変換を行う。

### 1. 参照名を削除しても成立する特徴へ分解する

```yaml
reference_request: "特定アーティスト風"
allowed_abstraction:
  rhyme:
    density: medium_high
    placement: [internal, phrase_end]
    span: [2_mora, 4_mora]
  rhythm:
    subdivision: sixteenth_based
    timing: slightly_behind
    variation: burst_then_space
  narrative:
    viewpoint: first_person
    scene_density: high
    turn: reflective_last_quarter
  language:
    register: conversational
    image_concreteness: high
forbidden_carryover:
  - signature_phrases
  - rare_metaphors
  - proprietary_names
  - recognizable_adlibs
  - same_story_sequence
```

### 2. 独立した制作条件を最低三つ変える

次のうち最低三つを参照元から離す。

- 題材・対立
- 話者の立場
- 時代・場所
- 比喩領域
- セクション構造
- 韻母音の系列
- テンポ感・音価
- 結末の態度

単語だけ置換し、構文・場面順・韻位置を残すのは不十分である。

### 3. 出力の帰属を明確にする

- 「オリジナルのリリック」と表示する。
- 実在アーティストの未発表作・本人作とは称さない。
- 特徴を説明するときは「内部韻が多い」「会話調」「後半で視点が反転」のような一般語を使う。

## 既存リリックを扱うとき

### 参照資料に収録しない

- 商業曲の歌詞全文、長い抜粋、字幕、非公式書き起こしをスキルへ同梱しない。
- 技法の定義に必要な場合も、原則として自作の短い例を使う。
- 外部論文・書籍はURL、書誌、要点のみを台帳へ記録し、本文を転載しない。
- ユーザー提供テキストは、その依頼の分析用入力として扱い、恒久コーパスへ追加しない。

### 分析と生成を分ける

1. 既存文から、韻位置、発音列、構造、機能だけを抽出する。
2. 元の名詞、動詞、比喩、固有名詞、語順を捨てる。
3. 別の題材と意味設計を先に作る。
4. 新しい発音列と韻語を割り当てる。
5. 原文を見ずに初稿を書く。
6. 最後に近接監査を行う。

既存曲の続きを求められた場合は、同じ登場人物・場面・韻語を引き継がず、テーマだけを一般化した別作品として提案する。

## 独創性パイプライン

### A. 出典管理

各入力へ次のラベルを付ける。

| ラベル | 意味 | 利用方法 |
|---|---|---|
| `original_prompt` | ユーザーの設定・体験・素材 | 指示範囲で利用 |
| `user_supplied_reference` | ユーザー提供の既存文 | 分析対象。再利用は最小限 |
| `public_fact` | 事実・一般知識 | 正確性を確認して利用 |
| `technique_abstraction` | 一般化した作詞技法 | 利用可 |
| `generated_draft` | この作業で作った初稿 | 近接監査後に利用 |

### B. 独立した意味設計

韻語を探す前に、以下を一文ずつ決める。

- 誰が、いつ、どこで話すか
- 何を欲し、何が妨げるか
- 各4小節で何が変わるか
- 最後に何を残すか

既存曲の場面順を土台にしない。

### C. 音の設計

- 参照曲と異なる母音系列を選ぶ。
- 同じ位置へ同じ長さの韻を並べ続けない。
- 参照作品の特徴的な韻語ペアを再利用しない。
- 意味に必要な語を先に置き、その周囲へ韻を作る。

### D. 近接監査

自動照合は法的判定ではなく、再点検を促すヒューリスティックとして使う。

- 長い連続語句が入力参照と一致していないか。
- 希少な語の組み合わせが一致していないか。
- 同義語置換だけで構文が残っていないか。
- 比喩の「対象→動作→オチ」が同じでないか。
- セクション順、視点転換、最終行の機能まで一致していないか。
- 固有のアドリブや間投詞が残っていないか。

一般的な短句、慣用句、必要な固有名称の一致は機械的に違反とみなさない。逆に、一致率が低くても希少な比喩や物語構造が近ければ書き直す。

### E. 書き直し

近接が疑われる箇所は、単語置換ではなく次の順に変更する。

1. 行の意図
2. イメージ領域
3. 構文
4. 韻母音
5. リズム位置

最低でも二層以上を変える。

## 文化的真正性と話者設計

- AAVE、特定地域の方言、コミュニティ固有語を「ラップらしさ」の既定値にしない。
- 犯罪、差別、貧困、ギャング、薬物などを、話者の実体験として勝手に付与しない。
- ユーザーの実体験を扱う場合は、提供された範囲を越えて事実を補わない。
- 架空話者なら「架空」と内部設定で明示し、実在人物との混同を避ける。
- 方言を使う場合は、地域、話者、使用範囲を指定し、語尾だけの誇張にしない。
- 文化的背景が不明な場合は、標準的な口語から開始し、後で調整する。

ローカル化は、輸入した表面記号ではなく、自分の言語・場所・社会関係へ創造的に作り替える過程である。[src:manabe-2006]

## 依頼別の処理例

| 依頼 | 安全な変換 |
|---|---|
| 「Xと同じリリックを書いて」 | Xの一般技法を説明し、題材・構造・語彙・韻系列を変えたオリジナルを作る |
| 「Xの未発表ヴァース」 | 本人作の体裁を避け、指定テーマによる独立したオリジナルとして作る |
| 「この曲の続きを書いて」 | 続編ではなく、抽象テーマを受けた別話者・別場面の新作にする |
| 「この8小節をもっとXっぽく」 | Xの名前を技法ベクトルへ変換し、元の8小節自体も近接監査する |
| 「この歌詞を韻だけ変えて」 | 意味・構文・場面順まで既存作と同じなら、より広い再設計を提案する |
| 「この本人の声で読ませたい」 | リリック制作と声の本人性模倣を切り分け、本人を装わない読み方へ変更する |

## 最終チェック

- 特定アーティスト名を外しても、制作指示が具体的に成立するか。
- 既存作品の語句、希少比喩、場面順、韻語、オチを持ち越していないか。
- 一般技法を使いながら、題材と意味設計は独立しているか。
- 本人作・本人承認・本人音声と誤認させる表示がないか。
- ユーザー提供テキストを恒久資料へ追加していないか。
- 参照資料は書誌と要点に留まり、著作物本文を同梱していないか。
- 話者の文化的背景や経験を勝手に捏造していないか。
- 不安が残る箇所を、表面置換でなく意図・構文・音の複数層から書き直したか。

生成AIと著作権の法的整理は発展途上であり、訓練利用、生成物、デジタル・レプリカは論点が異なる。高リスクの公開・商用案件では、管轄に応じた専門家確認が必要である。[src:usco-generative-ai-training-2025], [src:usco-digital-replicas-2024]
